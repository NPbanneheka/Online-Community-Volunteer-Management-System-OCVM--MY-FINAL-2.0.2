OCVMS Ownership / Organization Security Fix Summary
===================================================

This version fixes the ownership authorization issue reported during final testing.

Security rules applied:
1. Admin can manage all events, community posts, comments, and support requests.
2. Organizer can manage records created by organizers from the same organization.
3. Organizer cannot edit/delete records created by a different organization.
4. Volunteer can only manage their own community posts, own comments, and own support requests.
5. Volunteer cannot edit/delete events.
6. UI buttons are hidden when the logged-in user is not allowed to manage that record.
7. Controller-level checks are also applied, so direct URL access is blocked.

Organization handling:
- Organizer registration now asks for Organization Name.
- Organizer profile editing requires Organization Name.
- Organization Name is used to decide same-organization access.
- Organizers in the same organization should use the same spelling of the organization name.

Run steps:
1. Restore database backup to your SQL Server instance.
2. Confirm appsettings.json DefaultConnection matches your SQL Server instance.
3. Run:
   dotnet clean .\OCVMS.csproj
   dotnet restore .\OCVMS.csproj
   dotnet build .\OCVMS.csproj
   dotnet run --project .\OCVMS.csproj

Current default connection string is configured for:
Server=.\SQLEXPRESS;Database=OCVMSDb;Trusted_Connection=True;MultipleActiveResultSets=true;TrustServerCertificate=True
